Azure Databricks ETLTest Automation Framework
PySpark + PyTest | CSV/TXT → Raw → Operational → Curated
A practical learning and interview reference for building reusable data-quality and reconciliation tests inside Azure Databricks.
Prepared for: Lingam D Reddy
1. Framework Goal
The purpose of this framework is to validate data at every stage of a Databricks ETL pipeline. PySpark performs scalable data comparisons and transformations, while PyTest provides repeatable test execution and assertions that mark validations as PASS or FAIL.
CSV / TXT    |    vSOURCE FILES    |  Source-to-Raw validations    vRAW LAYER    |  Raw-to-Operational validations    vOPERATIONAL LAYER    |  Operational-to-Curated validations    vCURATED LAYER    |    vPYTEST RESULTS: PASS / FAIL
2. Validation Strategy by Layer
Stage
Core validations
Source files
File/path accessibility, not empty, delimiter/columns, schema/format, record count
Source → Raw
Count reconciliation, missing/unexpected keys, schema/columns, ingestion completeness
Raw layer
Mandatory NULLs, duplicate primary keys, data types, allowed values
Raw → Operational
Transformations, filters, datatype conversions, rejected records, key reconciliation
Operational layer
NULLs, duplicates, business rules, referential/key integrity
Operational → Curated
Aggregations, derived metrics, transformations, incremental-load logic
Curated layer
Final business metrics, NULLs, duplicates, allowed values, data quality

5. Generic PySpark Data Reader
from pyspark.sql import DataFrameclass DataReader:    def __init__(self, spark):        self.spark = spark    def read_csv(self, path, delimiter=",", header=True) -> DataFrame:        return (self.spark.read                .option("header", str(header).lower())                .option("delimiter", delimiter)                .option("inferSchema", "true")                .csv(path))    def read_txt(self, path, delimiter="|") -> DataFrame:        return (self.spark.read                .option("header", "true")                .option("delimiter", delimiter)                .option("inferSchema", "true")                .csv(path))    def read_table(self, table_name) -> DataFrame:        return self.spark.table(table_name)    def read_sql(self, query) -> DataFrame:        return self.spark.sql(query)
6. Reusable Validation Library
from pyspark.sql import functions as Fclass DataValidator:    @staticmethod    def validate_record_count(source_df, target_df):        source_count = source_df.count()        target_count = target_df.count()        assert source_count == target_count, (            f"Record count mismatch: Source={source_count}, Target={target_count}"        )    @staticmethod    def validate_not_empty(df):        assert df.limit(1).count() > 0, "Dataset is empty"    @staticmethod    def validate_nulls(df, columns):        for column in columns:            null_count = df.filter(F.col(column).isNull()).count()            assert null_count == 0, f"{column} contains {null_count} NULL values"    @staticmethod    def validate_duplicates(df, key_columns):        duplicates = (df.groupBy(*key_columns).count()                        .filter(F.col("count") > 1))        duplicate_count = duplicates.count()        assert duplicate_count == 0, (            f"Found {duplicate_count} duplicate keys for {key_columns}"        )    @staticmethod    def validate_columns(df, expected_columns):        missing = set(expected_columns) - set(df.columns)        assert not missing, f"Missing columns: {missing}"    @staticmethod    def validate_allowed_values(df, column, allowed_values):        invalid_count = df.filter(~F.col(column).isin(allowed_values)).count()        assert invalid_count == 0, (            f"{column} contains {invalid_count} invalid rows"        )
7. Key Reconciliation
Record counts alone can pass even when the wrong records are present. A left-anti join identifies source keys missing from the target and target keys that are unexpected.
class Reconciliation:    @staticmethod    def validate_key_reconciliation(source_df, target_df, key_columns):        source_keys = source_df.select(*key_columns).distinct()        target_keys = target_df.select(*key_columns).distinct()        missing = source_keys.join(target_keys, key_columns, "left_anti")        unexpected = target_keys.join(source_keys, key_columns, "left_anti")        missing_count = missing.count()        unexpected_count = unexpected.count()        assert missing_count == 0, (            f"{missing_count} source keys are missing from target"        )        assert unexpected_count == 0, (            f"{unexpected_count} unexpected keys found in target"        )

10. Raw → Operational Transformation Tests
For transformation testing, calculate the expected value from Raw using the documented business rule and compare it with the actual value in Operational.
from pyspark.sql import functions as Fdef test_full_name_transformation(raw_df, operational_df):    expected = (raw_df        .withColumn("expected_full_name",            F.concat_ws(" ", F.col("first_name"), F.col("last_name")))        .select("customer_id", "expected_full_name"))    actual = operational_df.select("customer_id", "full_name")    comparison = expected.join(actual, "customer_id", "inner")    mismatches = comparison.filter(        ~F.col("expected_full_name").eqNullSafe(F.col("full_name"))    )    assert mismatches.count() == 0, (        f"Found {mismatches.count()} full_name transformation failures"    )def test_status_transformation(raw_df, operational_df):    expected = raw_df.select(        "customer_id", F.upper("status").alias("expected_status"))    actual = operational_df.select(        "customer_id", F.col("status").alias("actual_status"))    mismatches = expected.join(actual, "customer_id").filter(        ~F.col("expected_status").eqNullSafe(F.col("actual_status"))    )    assert mismatches.count() == 0

from pyspark.sql import functions as Fdef test_customer_total_amount(operational_df, curated_df):    expected = (operational_df.groupBy("customer_id")        .agg(F.sum("amount").alias("expected_amount")))    actual = curated_df.select(        "customer_id", F.col("total_amount").alias("actual_amount"))    mismatches = expected.join(actual, "customer_id", "full_outer").filter(        ~F.col("expected_amount").eqNullSafe(F.col("actual_amount"))    )    assert mismatches.count() == 0, (        f"Found {mismatches.count()} aggregate mismatches"    )

13. How an Assertion Fits
source_count = source_df.count()target_count = target_df.count()assert source_count == target_count, "Count mismatch"
The Spark code calculates the actual result. The assertion is the final checkpoint. If the condition is True, the test passes; if False, PyTest reports a failed test and displays the message.

15. Running Tests in Databricks
Use Python test files named test_*.py or *_test.py and test functions prefixed with test.
Attach tests to an appropriate Databricks compute environment when Spark/table access is required.
Run tests from Databricks workspace test tooling where available, or execute pytest in your project workflow.
Keep reusable framework code separate from individual pipeline test suites.
pytest -v tests/
16. Framework Improvements for a Real Project
Make validations configuration-driven using JSON/YAML or control tables.
Capture failed record samples to an audit Delta table instead of only returning a count.
Add batch_id/load_date filters so validations compare the correct incremental load.
Add datatype and schema comparison from table metadata.
Add referential-integrity tests between fact and dimension/business tables.
Write execution metadata: run_id, pipeline, layer, test_case, expected, actual, result, timestamp.
Integrate test execution into your Databricks job or CI/CD workflow.
For very large datasets, avoid collect(); compare with Spark joins, aggregates and hashes at distributed scale.

20. Sequential Execution Flow: What Runs First and Why
This section explains the framework in the exact order you should imagine it executing. Read it from Step 1 to Step 10 whenever the class, object, fixture, DataFrame, validation, or assertion feels confusing.
Step 1 - Databricks provides the Spark session
The test starts on Databricks compute. The SparkSession named spark is the entry point used to read files, tables, and execute Spark SQL.
spark
Step 2 - PyTest provides spark through the fixture
The session fixture returns the active SparkSession. Tests and data-loading fixtures can request spark as an argument.
@pytest.fixture(scope="session")def spark():    return SparkSession.builder.getOrCreate()
Step 3 - Create the DataReader object
We create one object from the DataReader class and give it Spark. Creating the object automatically runs __init__.
reader = DataReader(spark)
Step 4 - __init__ stores Spark inside the object
Python automatically calls __init__(self, spark). self represents the new reader object. self.spark = spark stores the SparkSession so every reader method can reuse it.
def __init__(self, spark):    self.spark = spark
Step 5 - Read the source file
We ask the reader object to execute its read_csv method. The method uses self.spark.read and returns a Spark DataFrame. That returned DataFrame is stored in source_df.
source_df = reader.read_csv(source_path)
Step 6 - Read the Raw table
The same reader object already remembers Spark, so we do not pass spark again. read_table returns the Raw table as another Spark DataFrame.
raw_df = reader.read_table("catalog.raw.customer")
Step 7 - Data is now ready for comparison
At this point source_df and raw_df are Spark DataFrames. Validation code works on these DataFrames using count, filter, groupBy, joins, and column expressions.
source_count = source_df.count()raw_count = raw_df.count()
Step 8 - Execute a validation
A reusable validation method receives the two DataFrames and calculates the actual values that need to be compared.
DataValidator.validate_record_count(source_df, raw_df)
Step 9 - Assertion decides PASS or FAIL
Inside the validation, assert checks the expected condition. Equal counts mean PASS. Different counts raise AssertionError and PyTest marks the test as failed.
assert source_count == raw_count, (    f"Count mismatch: Source={source_count}, Raw={raw_count}")
Step 10 - Repeat for the remaining Source-to-Raw tests
The same loaded DataFrames can be validated for mandatory NULLs, duplicate keys, expected columns, and missing/unexpected keys. This is why the reader and validation utilities are reusable.
validate_nulls(raw_df, mandatory_columns)validate_duplicates(raw_df, primary_key)validate_key_reconciliation(source_df, raw_df, primary_key)

21. Basic to Advanced ETL Transformation Testing
Transformation testing is different from simple source-to-target comparison. The framework should calculate the expected value from the earlier layer using the documented business rule, then compare that expected value with the actual value produced in the next layer.
EARLIER LAYER         BUSINESS RULE          EXPECTED              NEXT LAYERRaw value      --->     transformation  ---> calculated value ---> actual value                                                     |                 |                                                     +------compare----+                                                            |                                                         PASS/FAIL
21.1 Transformation Progression
Basic: trim spaces, uppercase/lowercase, concatenate columns, replace/default NULL values.
Intermediate: datatype casting, date standardization, conditional CASE/WHEN rules, filtering, derived numeric columns.
Advanced: multi-table lookup joins, aggregations, window functions, deduplication with latest-record logic, SCD Type 2 and incremental-load rules.
21.2 Basic Transformation 1: Trim Whitespace
Requirement: Raw first_name may contain leading or trailing spaces. Operational first_name must be trimmed.
expected = raw_df.select(    "customer_id",    F.trim("first_name").alias("expected_first_name"))actual = operational_df.select(    "customer_id",    F.col("first_name").alias("actual_first_name"))mismatches = expected.join(actual, "customer_id").filter(    ~F.col("expected_first_name").eqNullSafe(F.col("actual_first_name")))assert mismatches.count() == 0
21.3 Basic Transformation 2: Uppercase / Lowercase
Requirement: Raw status active/inactive must become ACTIVE/INACTIVE in Operational.
expected = raw_df.select(    "customer_id",    F.upper("status").alias("expected_status"))actual = operational_df.select(    "customer_id",    F.col("status").alias("actual_status"))assert expected.join(actual, "customer_id").filter(    ~F.col("expected_status").eqNullSafe(F.col("actual_status"))).count() == 0
21.4 Basic Transformation 3: Concatenation
Requirement: first_name and last_name are combined into full_name.
expected = raw_df.select(    "customer_id",    F.concat_ws(" ", F.trim("first_name"), F.trim("last_name"))     .alias("expected_full_name"))
21.5 Basic Transformation 4: NULL Defaulting
Requirement: if country is NULL, Operational should store UNKNOWN.
expected = raw_df.select(    "customer_id",    F.coalesce(F.col("country"), F.lit("UNKNOWN")).alias("expected_country"))
21.6 Intermediate Transformation 1: Data Type Casting
Requirement: a source amount received as text must become Decimal(18,2) in Operational. Test both the schema and the converted values.
from pyspark.sql.types import DecimalTypeexpected = raw_df.select(    "customer_id",    F.col("amount").cast(DecimalType(18, 2)).alias("expected_amount"))actual_type = dict(operational_df.dtypes)["amount"]assert actual_type == "decimal(18,2)", f"Unexpected type: {actual_type}"
21.7 Intermediate Transformation 2: Date Standardization
Requirement: source date text is parsed into a DateType column.
expected = raw_df.select(    "customer_id",    F.to_date("order_date", "dd-MM-yyyy").alias("expected_order_date"))actual = operational_df.select(    "customer_id",    F.col("order_date").alias("actual_order_date"))
21.8 Intermediate Transformation 3: Conditional Business Rule
Requirement: customers with total_spend >= 100000 are GOLD, >= 50000 are SILVER, otherwise BRONZE.
expected = raw_df.select(    "customer_id",    F.when(F.col("total_spend") >= 100000, "GOLD")     .when(F.col("total_spend") >= 50000, "SILVER")     .otherwise("BRONZE")     .alias("expected_segment"))
21.9 Intermediate Transformation 4: Derived Numeric Column
Requirement: net_amount = quantity * unit_price - discount_amount.
expected = operational_df.select(    "order_id",    (F.col("quantity") * F.col("unit_price") - F.col("discount_amount"))      .alias("expected_net_amount"))
21.10 Intermediate Transformation 5: Filter Rule
Requirement: only valid, non-deleted records move from Raw to Operational. For filter transformations, do not expect Raw and Operational counts to be identical; calculate the expected filtered dataset first.
expected_df = raw_df.filter(    (F.col("is_valid") == True) &    (F.col("is_deleted") == False))assert expected_df.count() == operational_df.count()

21.15 Advanced Transformation 5: SCD Type 2 Validation
For an SCD Type 2 dimension, validate the behavior rather than only comparing one source row with one target row. Typical checks include exactly one current row per business key, expired rows having an end date, current rows having the expected current flag, and no overlapping effective periods.
# Example invariant: only one current record per customerinvalid_current = (curated_customer_dim    .filter(F.col("is_current") == True)    .groupBy("customer_id")    .count()    .filter(F.col("count") > 1))assert invalid_current.count() == 0
21.16 Advanced Transformation 6: Incremental / Delta Load
For incremental testing, compare the current batch rather than the full historical dataset. Filter source and target using the appropriate batch_id/load timestamp/watermark before executing count, key, and transformation validations.

21.17 Generic Transformation Comparison Helper
Once you understand each transformation individually, reduce repeated comparison code with a generic helper. The transformation itself should remain readable in the test so the business rule is obvious.
class TransformationValidator:    @staticmethod    def validate_column(        expected_df,        actual_df,        key_columns,        expected_column,        actual_column    ):        actual = actual_df.select(            *key_columns,            F.col(actual_column).alias("actual_value")        )        expected = expected_df.select(            *key_columns,            F.col(expected_column).alias("expected_value")        )        mismatches = (expected            .join(actual, key_columns, "full_outer")            .filter(~F.col("expected_value").eqNullSafe(F.col("actual_value"))))        mismatch_count = mismatches.count()        assert mismatch_count == 0, f"Found {mismatch_count} transformation mismatches"

21.19 How to Think in an Interview
For every transformation, explain the same four-stage pattern: understand the business rule, calculate expected output from the earlier layer using independent PySpark logic, join expected and actual using the business key, then assert that the mismatch count is zero. For filters and incremental loads, first define the comparable population before reconciling counts or keys.
